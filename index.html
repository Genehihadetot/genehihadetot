Pas 1 — Crear el correu de la comunitat

Necessites un correu electrònic dedicat a la teva comunitat. No uses el teu correu personal perquè el compartiràs a la política de privacitat de l'app i servirà de contacte públic.

1 Anar a Gmail

Obre el navegador i ves a gmail.com.

2 Crear un compte nou

Fes clic a Crear compte (o Create account). Tria Per a ús personal.

3 Escollir el nom del correu

Al camp Nom d'usuari, escriu el nom que vols per al correu de la comunitat. Per exemple: hihadetot.lamevacomunitat. El correu final serà hihadetot.lamevacomunitat@gmail.com. Tria un nom relacionat amb la teva comunitat.

4 Crear la contrasenya

Escriu una contrasenya segura (mínim 8 caràcters, amb majúscules, minúscules i números). Guarda-la en un lloc segur: si la perds, perdràs l'accés al correu de la comunitat.

5 Completar el registre

Google et demanarà el teu número de telèfon per verificar el compte. Introdueix-lo, rep el codi de verificació i entra'l. Omple la resta de dades que demani (nom, data de naixement) i accepta les condicions.

6 Guardar les dades

Apunta en un document de text segur:

  • Correu: el-teu-nom@gmail.com → aquest serà el teu posa_aqui_correu
  • Contrasenya del correu

Usaràs aquest correu per registrar-te a Supabase, Cloudinary, GitHub i Vercel. És el correu central de la teva instal·lació.

Pas 2 — Crear el compte de Supabase

Supabase és el servei que guarda totes les dades de l'app: els usuaris, els articles, els missatges, les cues, etc. El pla gratuït és suficient per a una comunitat de mida mitjana.

1 Crear el compte

Ves a supabase.com i fes clic a Start your project. Pots registrar-te amb el correu de la comunitat que acabes de crear.

2 Crear un projecte nou

Un cop dins del panell, fes clic a New project. Et demanarà:

  • Name: el nom del teu projecte (per exemple: hihadetot-lamevacomunitat). Qualsevol nom serveix.
  • Database Password: escriu una contrasenya llarga i segura. Guarda-la.
  • Region: tria West EU (Ireland) per tenir el servidor a prop.

Fes clic a Create new project i espera uns 2 minuts.

3 Obtenir la URL i la clau pública

Al panell del projecte, fes clic a Project Settings (icona d'engranatge ⚙️ a la barra lateral) i després a API. Veuràs dues dades. Copia-les i guarda-les:

Valor al panellGuardar com aExemple de format
Project URLposa_aqui_supabase_urlhttps://abcdefgh.supabase.co
anon public (dins Project API keys)posa_aqui_supabase_anon_keyeyJhbGci... (molt llarg)
Hi ha una altra clau anomenada service_role. Guarda-la apart. Aquesta clau dona accés total a la base de dades i mai va a l'HTML. La necessitaràs al pas 10 (Edge Function). Anota-la com a posa_aqui_supabase_service_role_key però en un lloc segur i separat.
4 Desactivar la confirmació de correu

A la barra lateral esquerra fes clic a Authentication i després a Settings. Busca l'apartat Email Confirmations i assegura't que està desactivat (el toggle en gris). L'app no usa confirmació de correu.

Pas 3 — Crear les taules de la base de dades

Ara has de crear totes les taules que l'app necessita. Ho faràs enganxant codi SQL a l'editor de Supabase. No cal entendre el codi, només cal copiar-lo i executar-lo.

1 Obrir l'editor SQL

A la barra lateral del teu projecte Supabase, fes clic a SQL Editor. Fes clic a New query.

2 Executar el SQL complet

Copia tot el bloc de codi següent, enganxa'l a l'editor i fes clic a Run (o Ctrl+Enter):

-- Extensió per generar IDs únics automàticament
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- ── TAULA: perfils ──────────────────────────────────────────
CREATE TABLE public.perfils (
  id                      uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  nom                     text NOT NULL,
  poblacio                text,
  created_at              timestamptz DEFAULT now(),
  denunciat_count         int4 DEFAULT 0,
  actiu                   bool DEFAULT true,
  notificacions_missatges bool DEFAULT true,
  notificacions_articles  bool DEFAULT true,
  notificacions_cua       bool DEFAULT true,
  telefon                 text
);

-- ── TRIGGER: crear perfil automàticament quan es registra un usuari ──
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger AS $$
BEGIN
  INSERT INTO public.perfils (id, nom, poblacio, telefon)
  VALUES (
    NEW.id,
    COALESCE(NEW.raw_user_meta_data->>'nom', ''),
    COALESCE(NEW.raw_user_meta_data->>'poblacio', ''),
    NEW.raw_user_meta_data->>'telefon'
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();

-- ── TAULA: normes_acceptades ────────────────────────────────
CREATE TABLE public.normes_acceptades (
  user_id     uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  accepted_at timestamptz DEFAULT now()
);

-- ── TAULA: articles ─────────────────────────────────────────
-- foto1_url i foto2_url guarden la URL de Cloudinary

-- ── TAULA: busco ────────────────────────────────────────────

CREATE TABLE public.cua (

CREATE TABLE public.denunciesusuari (

-- ── TAULA: push_subscriptions ───────────────────────────────
-- La restricció UNIQUE (user_id, endpoint) és necessària:

CREATE TABLE public.push_subscriptions (

-- ── TAULA: comptadors ───────────────────────────────────────
-- Totals acumulats; l'app els incrementa en cada operació
CREATE TABLE public.comptadors (

Pas 4 — Crear el bucket d'imatges

El bucket fotos-articles és una carpeta al núvol de Supabase. Les fotos dels articles es pugen a Cloudinary, però el codi d'edició d'articles utilitza aquest bucket per eliminar fotos antigues quan l'usuari les substitueix. Cal que existeixi per evitar errors.

1 Anar a Storage

A la barra lateral del teu projecte Supabase, fes clic a Storage.

2 Crear el bucket

Fes clic a New bucket. Omple el formulari:

  • Name: escriu exactament fotos-articles (en minúscules, amb guió)
  • Public bucket: activa-ho (toggle en verd)

Fes clic a Save.

3 Crear les polítiques del bucket

Torna a l'SQL Editor, crea una nova consulta i executa:

CREATE POLICY "fotos-articles: lectura pública"
ON storage.objects FOR SELECT
USING (bucket_id = 'fotos-articles');

CREATE POLICY "fotos-articles: pujada autenticada"
ON storage.objects FOR INSERT
WITH CHECK (bucket_id = 'fotos-articles' AND auth.role() = 'authenticated');

CREATE POLICY "fotos-articles: eliminació autenticada"
ON storage.objects FOR DELETE
USING (bucket_id = 'fotos-articles' AND auth.role() = 'authenticated');

CREATE POLICY "fotos-articles: actualització autenticada"
ON storage.objects FOR UPDATE
USING (bucket_id = 'fotos-articles' AND auth.role() = 'authenticated');

Pas 5 — Activar els missatges en temps real

Perquè els missatges del xat, els avisos i la plaça del poble apareguin a l'instant sense haver de recarregar la pàgina, cal activar Realtime per a tres taules.

1 Executar el SQL d'activació

A l'SQL Editor, crea una nova consulta i executa:

-- Missatges del xat privat
ALTER PUBLICATION supabase_realtime ADD TABLE public.missatges;
-- Avisos del sistema (cua, denúncies...)
ALTER PUBLICATION supabase_realtime ADD TABLE public.avisos;
-- La plaça del poble (xat obert de la comunitat)
ALTER PUBLICATION supabase_realtime ADD TABLE public.xat_comunitat;
✅ Fet. Les tres taules ara envien actualitzacions en temps real.

Pas 6 — Crear el compte de Cloudinary

Cloudinary emmagatzema les fotografies dels articles i dels events de l'Agenda. El pla gratuït inclou 25 GB d'espai, més que suficient per a una comunitat.

Qui usa Cloudinary i per a què:
  • Fotos dels articles → Cloudinary, a la carpeta posa_aqui_cloudinary_folder
  • Fotos dels events de l'Agenda → Cloudinary, a la subcarpeta posa_aqui_cloudinary_folder/agenda
Les fotos de Cloudinary no s'esborren des de l'app. Si cal netejar-les, s'ha de fer manualment des del dashboard de Cloudinary.
1 Crear el compte

Ves a cloudinary.com i fes clic a Sign up for free. Registra't amb el correu de la comunitat.

2 Obtenir el Cloud name

Un cop dins del panell (Dashboard), veuràs a dalt a l'esquerra el teu Cloud name: és una paraula curta com dv8abc123. Copia'l i guarda'l com a posa_aqui_cloudinary_cloud_name.

3 Crear l'upload preset
  1. Fes clic a l'engranatge ⚙️ (Settings) a la barra lateral.
  2. Fes clic a la pestanya Upload.
  3. Baixa fins a Upload presets i fes clic a Add upload preset.
  4. Configura:
    • Preset name: escriu el nom que vulguis per a la teva comunitat. Guarda'l com a posa_aqui_cloudinary_upload_preset.
    • Signing mode: tria Unsigned. (Si no el canvies, les pujades no funcionaran.)
    • Folder: deixa'l completament buit. No hi escriguis res.
  5. Fes clic a Save.
Per què la carpeta ha de ser buida: l'app envia la carpeta de destinació automàticament en cada pujada. Les fotos dels articles van a posa_aqui_cloudinary_folder i les de l'Agenda a posa_aqui_cloudinary_folder/agenda. Si el preset ja té una carpeta, les rutes quedaran incorrectes.
4 Decidir el nom de la carpeta principal

Tria un nom curt i sense espais per a la carpeta principal de la teva comunitat a Cloudinary (per exemple: lacomunitat o hihadetot-montnegre). Aquest serà el valor de posa_aqui_cloudinary_folder que posaràs a l'HTML al pas 11.

Pas 7 — Generar les claus de notificació push (VAPID)

Les notificacions push necessiten un parell de claus de seguretat (clau pública i clau privada) que generes tu mateix una sola vegada. La clau pública va a l'HTML; la privada, mai.

1 Instal·lar Node.js

Ves a nodejs.org i descarrega la versió LTS. Executa l'instal·lador seguint tots els passos per defecte.

2 Obrir el terminal
  • Windows: tecla Windows + R, escriu cmd, prem Enter.
  • Mac: obre Terminal (Aplicacions → Utilitats → Terminal).
3 Generar les claus

Escriu aquesta comanda exacta i prem Enter:

npx web-push generate-vapid-keys

Si demana confirmació («Ok to proceed? (y)»), escriu y i prem Enter.

Veuràs dues línies. Copia-les totes dues i guarda-les:

Public Key:
BJ4xyz...llarga seqüència...    ← és el teu posa_aqui_vapid_public_key

Private Key:
abc123...llarga seqüència...    ← és el teu posa_aqui_vapid_private_key (mai a l'HTML)
Guarda les dues claus en un lloc segur. La clau privada mai es posa a l'HTML. Si les perds hauràs de generar-ne unes de noves i restablir les subscripcions de tots els usuaris.

Pas 8 — Crear la funció de notificacions push

Aquesta funció s'executa dins de Supabase i s'encarrega d'enviar les notificacions push als dispositius dels usuaris. El seu nom ha de ser exactament hyper-processor i no es pot canviar perquè l'HTML el referencia directament.

1 Anar a Edge Functions

Al panell del teu projecte Supabase, fes clic a Edge Functions a la barra lateral.

2 Crear la funció

Fes clic a Create a new function. Escriu el nom exacte: hyper-processor. Confirma.

S'obrirà un editor de codi. Esborra tot el que hi ha i enganxa el codi següent:

import { createClient } from 'https://esm.sh/@supabase/supabase-js@2'
import webpush from 'npm:web-push'

const VAPID_PUBLIC  = Deno.env.get('VAPID_PUBLIC_KEY')!
const VAPID_PRIVATE = Deno.env.get('VAPID_PRIVATE_KEY')!
const SUPABASE_URL  = Deno.env.get('SUPABASE_URL')!
const SERVICE_KEY   = Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!

webpush.setVapidDetails('mailto:posa_aqui_correu', VAPID_PUBLIC, VAPID_PRIVATE)

Deno.serve(async (req) => {
  if (req.method === 'OPTIONS') {
    return new Response('ok', { headers: {
      'Access-Control-Allow-Origin': '*',
      'Access-Control-Allow-Headers': 'authorization, content-type'
    }})
  }
  const body = await req.json()
  const sb = createClient(SUPABASE_URL, SERVICE_KEY)
  let query = sb.from('push_subscriptions').select('endpoint, p256dh, auth, user_id')
  if (body.user_id) {
    query = query.eq('user_id', body.user_id)
  } else if (body.tots_usuaris) {
    if (body.exclou_user_id) query = query.neq('user_id', body.exclou_user_id)
    if (body.notif_camp) {
      const { data: perfils } = await sb.from('perfils').select('id').eq(body.notif_camp, true)
      if (perfils) query = query.in('user_id', perfils.map((p: any) => p.id))
    }
  }
  const { data: subs } = await query
  if (!subs || subs.length === 0)
    return new Response(JSON.stringify({ sent: 0 }), { headers: { 'Content-Type': 'application/json' } })
  const payload = JSON.stringify({
    title: body.title || 'Hi ha de tot',
    body:  body.body  || '',
    tag:   body.tag   || 'hihadetot',
    url:   body.url   || '/'
  })
  let sent = 0
  for (const sub of subs) {
    try {
      await webpush.sendNotification({ endpoint: sub.endpoint, keys: { p256dh: sub.p256dh, auth: sub.auth } }, payload)
      sent++
    } catch (e: any) {
      if (e.statusCode === 410 || e.statusCode === 404)
        await sb.from('push_subscriptions').delete().eq('endpoint', sub.endpoint)
    }
  }
  return new Response(JSON.stringify({ sent }), { headers: { 'Content-Type': 'application/json' } })
})

Pas 13 — Publicar l'app a Internet amb Vercel

Vercel agafa els fitxers de GitHub i els publica a Internet. Cada vegada que actualitzis a GitHub, Vercel publica la nova versió automàticament.

1 Crear el compte de Vercel

Ves a vercel.com i fes clic a Sign Up. La manera més fàcil és triar Continue with GitHub i autoritzar la connexió.

2 Importar el repositori
  1. Fes clic a Add New… → Project.
  2. Veuràs la llista dels teus repositoris de GitHub. Fes clic a Import al costat del teu repositori.
  3. A la pantalla de configuració, no cal canviar res. Fes clic a Deploy.
3 Obtenir la URL de l'app

Nota sobre la política de privacitat

⚖️ Avís legal important: la plantilla inclou una política de privacitat de referència. Aquesta política no és automàticament vàlida per a la teva comunitat. Cada instal·lació és una entitat diferent amb un responsable diferent i unes circumstàncies pròpies.

Abans de posar l'app en producció, has de revisar i adaptar la política de privacitat a la teva situació real: qui és el responsable del tractament, quines dades es recullen, durant quant de temps es conserven, quins proveïdors s'utilitzen, etc.

Si tens dubtes legals, consulta un professional. No és suficient canviar els noms i el correu.

A l'HTML, els camps que has de personalitzar a la política de privacitat estan marcats com a posa_aqui_nom_entitat, posa_aqui_correu, posa_aqui_url_vercel i posa_aqui_data_politica_privacitat.
